# 启动方式说明

> 本项目支持两种启动方式：**原生 ROS2 环境** 和 **Docker 容器化环境**。推荐使用 Docker 方式以获得更好的环境一致性。

## 方式一：Docker 容器化启动（推荐）

参考 ROS2-start 项目架构，提供统一的容器管理脚本。

### 环境要求

- Ubuntu 24.04 LTS
- Docker 20.10+
- NVIDIA Container Toolkit（GPU 加速）
- X11 环境（用于显示 Gazebo/RViz）

> **重要**: 本项目基于 ROS2 **Jazzy** (非 Humble)，使用 Gazebo 新版。

### 快速启动

```bash
cd /media/wht/J/Auto-driving/slam/仿真SLAM/turtlebot3_simulations

# 1. 授权 X11 访问（首次执行）
xhost +local:docker

# 2. 启动容器
./turtlebot3_simulations.sh start

# 3. 编译项目
./turtlebot3_simulations.sh build

# 4. 启动仿真（任选其一）
./turtlebot3_simulations.sh empty_world        # 空世界
./turtlebot3_simulations.sh turtlebot3_world   # World 场景
./turtlebot3_simulations.sh turtlebot3_house   # House 场景
./turtlebot3_simulations.sh fake_node          # 仅 RViz（无 Gazebo）
```

### 完整命令列表

| 命令 | 说明 |
|------|------|
| `start` | 启动/创建 Docker 容器 |
| `stop` | 停止容器 |
| `rm` | 删除容器 |
| `shell` | 进入容器 Bash |
| `build` | 编译项目 (`colcon build`) |
| `empty_world` | 启动 Gazebo 空世界 |
| `turtlebot3_world` | 启动 World 场景（有障碍物） |
| `turtlebot3_house` | 启动 House 室内场景 |
| `fake_node` | 启动 Fake Node (RViz only) |
| `dqn_stage1~4` | 启动 DQN 强化学习场景 |
| `rviz` | 启动 RViz2 可视化 |
| `teleop` | 启动键盘控制 |
| `turtlebot3_drive` | 启动自动避障演示 |
| `model <name>` | 设置机器人模型 (burger\|waffle\|waffle_pi) |

### VSCode Dev Container 集成

1. 用 VSCode 打开项目目录
2. `Ctrl+Shift+P` → `Dev Containers: Reopen in Container`
3. 等待容器启动，即可开始开发

> 详细配置见 `.devcontainer/` 目录，完整文档见 `docs/Docker启动指南.md`

## 方式二：原生 ROS2 环境启动

适用于已安装 ROS2 Jazzy 的宿主机环境。

### 前提条件

```bash
# 确认已安装
ros2 --help | head -1              # 应显示 Jazzy
ros2 pkg list | grep turtlebot3   # 应显示相关包
```

### 启动步骤

```bash
# 1. 设置环境变量
export TURTLEBOT3_MODEL=burger  # burger | waffle | waffle_pi

# 2. 编译项目
cd /media/wht/J/Auto-driving/slam/仿真SLAM/turtlebot3_simulations
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install

# 3. 加载环境
source install/setup.bash

# 4. 启动仿真
ros2 launch turtlebot3_gazebo empty_world.launch.py
```

### 常用启动文件

```bash
# Gazebo 仿真
ros2 launch turtlebot3_gazebo empty_world.launch.py
ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py
ros2 launch turtlebot3_gazebo turtlebot3_house.launch.py

# DQN 强化学习
ros2 launch turtlebot3_gazebo turtlebot3_dqn_stage1.launch.py

# Fake Node（无 Gazebo）
ros2 launch turtlebot3_fake_node fake_node.launch.py
```

### 辅助节点

```bash
# RViz2 可视化
ros2 run rviz2 rviz2 -d $(ros2 pkg prefix turtlebot3_gazebo)/share/turtlebot3_gazebo/rviz/tb3_gazebo.rviz

# 键盘控制
ros2 run turtlebot3_teleop teleop_keyboard

# 自动避障演示
ros2 run turtlebot3_node turtlebot3_drive
```

## 启动流程详解

### Gazebo 仿真启动流程

以 `empty_world.launch.py` 为例：

```
1. 启动 Gazebo 服务器 (gzserver)
   └─ 加载 world 文件
   └─ 加载物理引擎

2. 启动 Gazebo 客户端 (gzclient)
   └─ 显示 3D 场景

3. 启动 robot_state_publisher
   └─ 加载 URDF
   └─ 发布 TF 变换

4. 启动 ros_gz_bridge
   └─ 加载 YAML 桥接配置
   └─ 映射 GZ topics ↔ ROS2 topics

5. 启动 ros_gz_image
   └─ 桥接摄像头图像

6. 生成机器人模型并放置在世界中
```

### Fake Node 启动流程

```
1. 启动 turtlebot3_fake_node
   └─ 读取参数文件（wheel_separation, wheel_radius）
   └─ 订阅 /cmd_vel
   └─ 发布 /odom, /joint_states, TF

2. 启动 robot_state_publisher
   └─ 加载 URDF
   └─ 发布 TF 变换

3. 启动 RViz2
   └─ 加载预设配置
   └─ 显示机器人模型和传感器数据
```

## 环境变量配置

### TURTLEBOT3_MODEL

选择机器人模型：

```bash
export TURTLEBOT3_MODEL=burger        # Burger（默认）
export TURTLEBOT3_MODEL=burger_cam    # Burger + Camera
export TURTLEBOT3_MODEL=waffle        # Waffle
export TURTLEBOT3_MODEL=waffle_pi     # Waffle Pi
```

### ROS_DOMAIN_ID

用于隔离多个 ROS2 实例：

```bash
export ROS_DOMAIN_ID=0  # 默认值，范围 0-101
```

## 常见问题

### Q: Gazebo 无法显示或黑屏

**A**: 检查 X11 转发：
```bash
# 确保执行了
xhost +local:docker

# 验证 DISPLAY 变量
echo $DISPLAY  # 应输出 :0 或类似值
```

### Q: 容器无法访问网络

**A**: 脚本已配置 `network_mode: host`，如遇问题检查防火墙：
```bash
sudo ufw status
```

### Q: 编译失败，找不到依赖

**A**: 确保依赖已安装：
```bash
# 容器内执行
source /opt/ros/jazzy/setup.bash
rosdep update
rosdep install --from-paths src -y --ignore-src
```

### Q: 如何切换机器人模型

**A**: 
- Docker 方式：`./turtlebot3_simulations.sh model waffle` 后重启容器
- 原生方式：`export TURTLEBOT3_MODEL=waffle` 后重新启动

## 方式对比

| 特性 | Docker 方式 | 原生方式 |
|------|-----------|----------|
| **环境一致性** | ✅ 镜像锁定，团队共享 | ⚠️ 依赖宿主机配置 |
| **安装复杂度** | ✅ 只需 Docker | ❌ 需安装完整 ROS2 |
| **系统污染** | ✅ 完全隔离 | ❌ 直接安装到系统 |
| **启动速度** | ⚠️ 首次拉取镜像较慢 | ✅ 直接运行 |
| **GUI 支持** | ⚠️ 需配置 X11 | ✅ 原生支持 |
| **调试便利** | ✅ VSCode Dev Container | ✅ 原生调试工具 |

> 💡 **建议**：开发阶段使用 Docker 保证环境一致；部署到真实机器人时使用原生方式减少开销。
